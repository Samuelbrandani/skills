# Notas por agente — Claude Code, Codex, Cursor e outros

O `SKILL.md` segue o padrão Agent Skills, então o método é o mesmo em todo lugar. O que muda entre agentes é o **harness**: como o MCP do Figma é autorizado, como as ferramentas se chamam, como o agente pergunta algo ao usuário e o que acontece quando o resultado de uma ferramenta é grande demais. Este arquivo é a tabela de tradução. Leia a coluna do seu agente uma vez; as fases do `SKILL.md` remetem a estas linhas.

| Necessidade | Claude Code | Codex (CLI / IDE / app) | Cursor, Gemini CLI, outros |
|---|---|---|---|
| **Instalar a skill** | `npx skills add Samuelbrandani/skills --skill figma-flutter -g` → `~/.claude/skills/` (ou `.claude/skills/`) | `npx skills add Samuelbrandani/skills --skill figma-flutter -a codex` → `~/.agents/skills/` (escopo de repo: `.agents/skills/`). O Codex re-escaneia as skills sozinho; reinicie se não aparecer | mesmo CLI com `-a <agente>`; o CLI conhece 80+ agentes |
| **Invocar** | automático num link do Figma, ou `/figma-flutter` | automático quando o pedido casa com a descrição, ou `$figma-flutter` | automático, ou a sintaxe de menção do agente |
| **MCP do Figma: conectar** | o plugin `figma` ou uma entrada MCP apontando para `https://mcp.figma.com/mcp` | em `~/.codex/config.toml`: `[features] rmcp_client = true` e `[mcp_servers.figma] url = "https://mcp.figma.com/mcp"` com `auth = "oauth"` (depois `codex mcp login figma`) ou `bearer_token_env_var = "FIGMA_OAUTH_TOKEN"`; no app do Codex: Plugins → Figma → Install | a config MCP do agente com a mesma URL |
| **MCP do Figma: autorizar (fase 0)** | se só existem `authenticate`/`complete_authentication`, chame `authenticate`, entregue a URL ao usuário e carregue as ferramentas reais com `ToolSearch("select:mcp__figma__whoami,…")` | `codex mcp login figma` num terminal, ou defina `FIGMA_OAUTH_TOKEN`; depois reinicie a sessão. Não há fluxo OAuth dentro do chat | por agente; normalmente um comando de login ou um token |
| **Nomes das ferramentas** | `mcp__figma__get_metadata`, `mcp__figma__get_design_context`, … | as mesmas ferramentas, expostas sob o nome do servidor (`figma`) — chame pelo nome puro (`get_metadata`) quando o agente as listar assim | idem |
| **Pré-requisito `figma-design-to-code` do `get_design_context`** | `ReadMcpResourceTool(server: "figma", uri: "skill://figma/figma-design-to-code/SKILL.md")`, depois `skillNames: "resource:figma-design-to-code"` | O Codex não lê recursos MCP pelo chat. Instale a skill curada (`npx skills add openai/skills --skill figma -a codex`) ou o plugin do Figma; o parâmetro `skillNames` é só de log e a chamada funciona sem ele — não trave nisso | se o agente não lê recursos, proceda como no Codex |
| **Resultados grandes** (`get_metadata` numa seção, `get_design_context` numa tela inteira) | o harness salva o resultado em arquivo; rode `scripts/figma_outline.py <arquivo>` | o resultado é **truncado** por orçamento de tokens. Chame `get_metadata` por frame de tela (não por seção) e `get_design_context` por seção da tela (header, corpo, rodapé). Aumente o orçamento no `config.toml` se precisar: `[mcp_servers.figma.tools.get_metadata] output_token_limit = 60000`. Se conseguir colar um resultado salvo num arquivo, o `figma_outline.py` continua funcionando | idem: nós menores primeiro |
| **Screenshots e download de assets** (`curl -L -o`) | shell comum | o sandbox pode bloquear rede; aprove o `curl` quando perguntar, ou libere rede no sandbox para a sessão. As URLs expiram em minutos, então baixe logo após a ferramenta responder | idem |
| **Perguntar o lote de decisões** | um `AskUserQuestion` com as quatro decisões | escreva as quatro decisões como lista numerada no chat, com a opção recomendada primeiro, e espere a resposta antes da fase 3 | idem, no chat |
| **Plano antes de código** (o `CLAUDE.md`/`AGENTS.md` do repo exige) | `EnterPlanMode`, plano com `references/plan-template.md`, `ExitPlanMode` para aprovação | escreva o arquivo de plano (`docs/plans/…` pelo template), mostre e espere um "vai" explícito no chat antes da fase 6 | idem |
| **Rodar os scripts** | ferramenta Bash | shell dentro do sandbox; os scripts são somente leitura e não usam rede. No Windows use `py -3 scripts\repo_scan.py` ou `scripts\repo_scan.ps1` | idem |
| **Testes do design probe** | `flutter test` pelo Bash | `flutter test` pelo shell; a primeira execução pode pedir aprovação para gravar `test/design/snapshots/*.json` | idem |
| **Arquivo de instruções do repo** | `CLAUDE.md` (e pais) | `AGENTS.md` (e pais); o scanner lista os dois | o arquivo do agente; o scanner lista `CLAUDE.md`, `AGENTS.md`, `ARCHITECTURE.md` |

O que não muda: as fases, as três tabelas do de-para, as regras de assets, o contrato de dado, os 12 eixos, os gates.
